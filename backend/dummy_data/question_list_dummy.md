## 1. 리서치 개요 및 조사 목적

* **조사 목적:**
OpenAI Codex 기반 모델의 뛰어난 순수 성능(추론 및 코드 생성 능력)에도 불구하고, 개발자들이 터미널 기반 작업에서 Anthropic의 Claude Code를 더 선호하거나 스위칭하는 **결정적 요인(UX/워크플로우/컨텍스트 관리 방식)을 파악**하고, OpenAI가 극복해야 할 제품적·전략적 갭(Gap)을 도출합니다.
* **타겟 스크리닝 기준 (대상자 선정):**
* 최근 1개월 이내에 **Claude Code**와 OpenAI 계열(Codex / ChatGPT / API 기반 CLI 툴)을 모두 실무 또는 개인 프로젝트에서 실제로 사용해 본 경험이 있는 개발자
* 하루 평균 2시간 이상 AI 코딩 에이전트 또는 터미널 기반 개발 환경을 사용하는 파워 유저



---

## 2. 10분 심층 인터뷰 가이드 (Moderator Guide)

### [Section 1] 도입 및 현황 파악 (Warm-up & Current Behavior) — 2분

* **목표:** 대상자의 주력 툴 체인 확인 및 자연스러운 라포 형성
* **핵심 질문:**
* *"현재 터미널이나 개발 환경에서 주로 어떤 AI 툴 조합(예: Claude Code, Cursor, OpenAI API 기반 툴 등)을 사용하고 계시나요?"*


* **Probing (탐색 갈래):**
* 평소 일상적인 코딩과 복잡한 리팩토링/디버깅 시 사용하는 툴이 다른가요?



---

### [Section 2] 핵심 탐색: Claude Code 선호 이유와 모델 성능의 괴리 (Core Exploration) — 4분 [우선순위: 최상]

* **목표:** 사용자가 체감하는 'Claude Code만의 대체 불가능한 가치'와 모델 스펙 간의 간극 확인
* **핵심 질문:**
* *"개발자들 사이에서 '모델 성능은 OpenAI가 최고인데, 터미널 작업은 결국 Claude Code를 켜게 된다'는 이야기가 있습니다. 본인도 이 말에 공감하시나요? 공감하신다면 그 결정적인 이유가 무엇인가요?"*


* **Probing (탐색 갈래):**
* **(UX/인터페이스 관점):** 터미널 환경에서 대화의 흐름이나 멀티스텝 작업 처리가 어떻게 더 편리하다고 느끼시나요?
* **(컨텍스트/에이전트 자율성 관점):** 대규모 코드베이스를 읽고 수정하는 과정에서 Claude가 의도를 더 잘 파악한다고 느끼는 구체적인 순간이 있나요?



---

### [Section 3] 마찰 지점 및 OpenAI 툴에 대한 아쉬움 (Pain Points & Gaps) — 3분 [우선순위: 상]

* **목표:** OpenAI 유저 경험에서의 병목과 이탈 원인 정조준
* **핵심 질문:**
* *"반대로, OpenAI 모델이나 관련 툴을 쓰면서 '아, 이 부분 때문에 결국 흐름이 끊긴다'거나 답답하다고 느꼈던 경험(Pain Point)은 무엇인가요?"*


* **Probing (탐색 갈래):**
* 프롬프트를 입력하고 결과물을 검토하는 과정에서 불필요하게 개입해야 하거나 수동으로 수정해야 했던 번거로움이 있었나요?
* 속도, 비용(토큰), 혹은 에이전트의 자율성 중 어떤 요소가 가장 아쉬웠나요?



---

### [Section 4] 클로징 및 미래 제안 (Closing & Feature Request) — 1분

* **목표:** OpenAI가 나아갈 방향에 대한 최종 인사이트 수집
* **핵심 질문:**
* *"만약 내일 당장 OpenAI가 터미널 기반 개발 경험을 혁신적으로 바꿀 단 하나의 기능을 내놓는다면, 어떤 모습이어야 할까요?"*
