## 1. 기획 및 유저 플로우 분석

인터뷰이(답변자)의 흐름은 다음과 같은 단계로 진행됩니다.

```mermaid
graph TD
    A[1. 일회용 링크 접속] --> B{세션 ID 유무?}
    B -- 없음 -- > C[Idle 상태: 세션 링크 필요 안내]
    B -- 있음 -- > D[2. PermissionGate: 카메라/마이크 권한 & 녹음 고지 동의]
    D -- 동의 완료 -- > E{세션 상태 확인}
    E -- 세션 미시작 (created) -- > F[3. WaitingScreen: 대기 화면]
    E -- 세션 시작됨 (running) -- > G[4. InterviewStage: AI 질문 & 답변 창]
    F -- 관리자가 세션 시작 -- > G
    G -- 인터뷰 종료 (ended) -- > H[5. 종료 안내 & 퇴장 화면]
```

### 1-1. 화면 상태 설계
- **Idle (링크 없음)**: 세션 링크가 올바르지 않거나 없을 때 나타나는 단순 안내.
- **Permission Gate (권한/동의 단계)**:
  - 카메라 및 마이크 사용 권한 체크 (Web API 테스트 및 안내).
  - 녹화/참관 고지 확인 및 개인정보 수집/녹음 동의 체크박스.
- **Waiting Screen (대기 단계)**:
  - 세션이 연결되었으나 백엔드 세션 상태가 `created`인 경우, "진행자가 인터뷰를 시작할 때까지 잠시 대기해 주세요"라는 상태 표시 및 아바타/오브가 차분하게 진동하는 대기 상태 UI 제공.
- **Interview Stage (진행 단계)**:
  - 세션 상태가 `running`이고 연결된 경우.
  - 상단: 세션 타이틀 및 실시간 연결 상태 뱃지.
  - 중앙: Azure TTS Avatar 폴백용 Orb 애니메이션 컴포넌트 & 현재 질문 텍스트 표시.
  - 하단 입력부: 답변을 작성해 전송할 수 있는 Composer (현재는 텍스트 입력 창, 추후 음성 입력 전환이 용이하도록 마이크 형태 배치 고려).
  - 하단 기록부: 지금까지 나눈 질문/답변 기록 (참관자 판단 근거나 instruction_id 노출은 철저히 배제).
- **Ended Screen (종료 단계)**:
  - 세션 상태가 `ended`이거나 WebSocket이 닫힌 경우, 인터뷰이에게 인터뷰가 끝났음을 인지시키고 창을 닫도록 안내.
